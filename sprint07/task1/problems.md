## 3. Полное описание трех инициатив

### Инициатива №1

| Поле | Решение |
| :--- | :--- |
| Инициатива без слова «AI» | Формирование упорядоченной очереди для ручной проверки операций на признаки транзитных операций, обналичивания и дробления платежей. |
| Какое действие изменится | Сотрудники осуществляют разбор не только наиболее крупных сумм, но и операций, находящихся в топе риск-ранжирования; при этом обязательные правила мониторинга продолжают функционировать в прежнем режиме. |
| Бизнес-действие | Выбор приоритетных операций для ручной проверки с отображением обоснования присвоения приоритета. |
| Объект и единица решения | Одна операция в контексте клиента, контрагента и временного интервала. |
| Момент | Асинхронно после получения события. На этапе пилотного проекта — расчет в теневом режиме (раз в сутки); в целевом контуре — в рамках установленного SLA существующего процесса финмониторинга. |
| Операция / модальность | Ранжирование, выявление аномалий; данные: таблица, временная метка, краткое текстовое назначение платежа. |
| Где нужна закономерность | Расчет оценки риска на основе поведенческого анализа, связей и текста назначения платежа. |
| Выход модели | Некалиброванный скоринг риска, признаки распределения вне обучающей выборки / неопределенности и локальные факторы влияния. |
| Бизнес-выход | Приоритезация очереди, объясняющие факторы, сигналы срабатывания правил, полнота данных и маршрутизация («проверить» / «контрольная выборка» / «стандартный поток»). |
| Источник правильного ответа | Экспертная метка согласно гайдлайнам и результатам арбитража; отдельно — исходные данные расследования и последующее формальное подтверждение. Данные сущности не должны смешиваться. |
| Конвейер | Извлечение детерминированных признаков → ранжирующая модель → калибровка / определение зоны воздержания → применение обязательных правил → формирование очереди → проверка человеком. |
| Чего не хватает | Отсутствие несмещенного эталона, точной стоимости регуляторных событий, параметров SLA и правового заключения по используемым полям и контурам данных. |
| Альтернативная постановка | Автоматическая классификация операций по признаку «схема» приостанавливается до накопления достаточного объема эталонных данных; требуется решение владельца о доле операций, которую допустимо направлять в контрольную выборку. |
| Вердикт | Гибрид |

### Инициатива №2

| Поле | Решение |
| :--- | :--- |
| Инициатива без слова «AI» | Преобразование страниц кредитной документации в текстовые блоки с указанием координат и уровня достоверности. |
| Какое действие изменится | Андеррайтер не занимается ручным переносом данных из документа, а проверяет подсвеченные результаты и корректирует ошибки. |
| Бизнес-действие | Создание верифицированного машиночитаемого слоя документа для последующей автоматизированной обработки. |
| Объект и единица решения | Страница документа; агрегированный объект — пакет кредитной заявки. |
| Момент | Асинхронно после загрузки пакета документов, до начала анализа андеррайтером. |
| Операция / модальность | Извлечение данных; типы данных: документ и изображение. |
| Где нужна закономерность | Определение ориентации/макета и распознавание символов; маршрутизация, логика схем и проверки выполняются стандартным кодом. |
| Выход модели | Страницы, текстовые блоки, текст, координаты, язык и уровень уверенности. |
| Бизнес-выход | Документ с визуальной подсветкой источника, статусом качества и очередью на ручную коррекцию. |
| Источник правильного ответа | Верифицированная транскрипция контрольного набора данных и исправления, внесенные андеррайтерами. |
| Чего не хватает | Распределение по форматам и качеству документов, требования к распознаванию рукописного ввода, правовые аспекты допустимости различных вариантов размещения данных. |
| Альтернативная постановка | Реализация только полнотекстового поиска по архиву либо извлечение только отдельных полей; приоритетность решения должен подтвердить владелец процесса андеррайтинга. |
| Вердикт | Гибрид |

### Инициатива №18

| Поле | Решение |
| :--- | :--- |
| Инициатива без слова «AI» | Формирование утвержденного набора финансовых показателей на основе отчетности и выписок с указанием периода, единицы измерения и ссылки на фрагмент документа. |
| Какое действие изменится | Вместо ручного поиска и переноса каждого поля андеррайтер проверяет предложенные значения и выявленные исключения. |
| Бизнес-действие | Автоматическое заполнение черновика структурированной финансовой карточки заявки с последующим подтверждением сотрудником. |
| Объект и единица решения | Одно финансовое поле документа; бизнес-агрегация — заявка и отчетный период. |
| Момент | Асинхронно после завершения процессов OCR/парсинга, до начала финансового анализа. |
| Операция / модальность | Структурированное извлечение данных; типы данных: документ, таблица и текст. |
| Где нужна закономерность | Сопоставление разнородных заголовков и таблиц с канонической схемой; арифметические расчеты и проверки логической допустимости выполняются стандартным кодом. |
| Выход модели | Код показателя, значение, единица измерения, валюта, период, уровень уверенности и ссылка на страницу/координаты. |
| Бизнес-выход | Валидированный черновик карточки, перечень выявленных противоречий и список полей, требующих ручного подтверждения. |
| Источник правильного ответа | Значения, подтвержденные или исправленные андеррайтерами, а также отдельно размеченный приёмочный набор данных. |
| Чего не хватает | Отсутствие канонического словаря показателей, данных об охвате типов форм документов, статистики исправлений и политики хранения данных. |
| Альтернативная постановка | Извлечение показателей только из стандартных форм; требуется решение владельца процесса о перечне 20–30 ключевых полей, обеспечивающих максимальную эффективность. |
| Вердикт | Гибрид |
