# Сводная таблица выявленных проблем

| Проблема | Признаки | Влияние на приложение |
| --- | --- | --- |
| Нет сквозной идемпотентности записи | `INT-005`: повторный `POST` создаёт дубли;<br> `INT-010`: идемпотентность только запланирована;<br>`SD-003`: повторная запись;<br> Дмитрий подтверждает отсутствие идемпотентности | Повтор после сетевой ошибки создаст несколько записей к врачу или несколько резервов лаборатории |
| Неопределённый результат платежа | `INT-001`: деньги списаны, но статус не зафиксирован;<br> обращения `SD-009` и `SD-004`;<br> Марина сообщает о повторных списаниях во время акции | Пациент может заплатить дважды либо получить ошибку после успешного списания;<br> запись останется неподтверждённой, а возврат потребует ручной сверки |
| Нет атомарности составной бизнес-операции | Запись, проверка полиса, платёж и резерв анализов выполняются разными системами;<br> отсутствуют оркестратор и компенсирующие операции;<br> колл-центр видит оплаченные, но не принятые записи | Частичный успех оставит деньги списанными, а врачебный или лабораторный слот незарезервированным;<br> восстановление возможно только вручную |
| Ненадёжная передача результатов из LIS | `INT-002`: FTP `425` и ручное восстановление;<br> `INT-008`: повторные XML создают дубли;<br> `INT-011`: сообщения застревают;<br> задержка достигает двух часов | Пациент и врач увидят устаревший, дублированный результат либо не увидят его вообще;<br> приложение увеличит нагрузку на колл-центр вместо её снижения |
| 1С не выдерживает пиковые запросы и имеет нестабильный контракт | `INT-003`: `503` при нагрузке более 50 RPS;<br> ответы дольше 30 секунд;<br> встречаются `null`, JSON вместо XML и изменения контракта без уведомления | Проверка ДМС заблокирует запись или даст ложный отказ;<br> синхронное ожидание нарушит целевой отклик и распространит отказ 1С на мобильный канал |
| Расписание ограничено блокировками единственной БД | `INT-009`: требуется read replica;<br> Дмитрий сообщает о блокировках PostgreSQL и потерянных изменениях расписания. | Рост до 500, а затем до 50 000 пользователей приведёт к таймаутам, устаревшим слотам и конкурентному бронированию одного времени |
| Уведомления могут теряться без восстановления | `INT-004`: лимиты RabbitMQ не документированы;<br>`SD-006` сообщает о недоставленных пуш-сообщениях | Пользователь не получит подтверждение записи, оплаты или готовности анализов;<br> повторная отправка и аудит доставки невозможны |
| Нет сквозной наблюдаемости | `INT-007`: отсутствует распределённая трассировка;<br> причины отказов и застрявших сообщений ищутся вручную | Поддержка не сможет быстро определить, на каком шаге произошёл сбой;<br> время восстановления и число повторных пользовательских запросов возрастут |
| Есть критические риски безопасности | `INT-006`: SQL injection в поиске пациентов;<br> в `SD-007` говорится, что врач видит чужого пациента | Злоумышленник может получить или изменить персональные и медицинские данные;<br> запуск приложения создаст новый публичный вектор атаки |
| Интеграции жёстко связаны и не защищены от каскадных отказов | Преобладают синхронные REST/SOAP/HTTP-вызовы;<br> для 1С, LIS и платежей не заданы единые timeout, retry, Circuit Breaker и fallback | Медленная внешняя система исчерпает потоки API и сделает всё приложение недоступным;<br> бесконтрольные повторы дополнительно усилят перегрузку |
