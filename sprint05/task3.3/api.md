# API предстоящих записей

## Артефакт

[openapi.yaml](openapi.yaml) содержит контракт `GET /api/v1/appointments` для
получения записей текущего пациента. Идентификатор пациента определяется по
проверенному Bearer access token и не принимается от клиента как параметр.

## Пагинация и версионирование

Для первой версии используется offset pagination с параметрами `limit` и
`offset`: она проста для мобильного клиента и подходит
для небольшого списка предстоящих записей. Ответ содержит `total`, `limit` и
`offset`, чтобы клиент мог определить наличие следующей страницы. Результаты
сортируются по `startAt`, затем по `id`, чтобы порядок был детерминированным.

Мажорная версия включена в URL: `/api/v1/...`. Совместимые изменения добавляются
в `v1`, а несовместимое изменение схемы или семантики публикуется как `/api/v2` с
периодом параллельной поддержки.
