# Поэтапный план миграции

| Этап / Срок | Содержание работ | Ожидаемый результат и критерии завершения |
| :--- | :--- | :--- |
| **1. Discovery** (Недели 1–2) | Инвентаризация таблиц, потоков и объемов данных; профилирование данных; определение владельцев; замер базовых показателей DQ и SLO. | Утвержденный реестр данных, бизнес-глоссарий, верифицированные критичные поля и критерии финансовой сверки. |
| **2. Foundation** (Недели 2–5) | Развертывание слоев Landing и Integration; настройка CDC/Outbox; внедрение Airflow, управления секретами (IAM/KMS), мониторинга и каталога метаданных. | Протестированная сквозная доставка данных с поддержкой повторных запросов, аудита и отслеживания происхождения. |
| **3. Customer Identity MVP** (Недели 3–8) | Реализация нормализации, создания связей, алгоритмов сопоставления, процессов ручной проверки и слияния/разделения записей. | Сформированная золотая запись (Golden Record) и глобальный ID; выборка ложноположительных срабатываний одобрена Data Steward. |
| **4. Unified Reporting MVP** (Недели 5–12) | Настройка потоков Batch/CDC из систем FU/RB в PostgreSQL DWH; маппинг продуктов; создание BI-витрин и механизмов сверки. | **Рубеж 3 месяцев:** обеспечена единая отчетность по клиентам, счетам, продуктам и операциям. |
| **5. Reference Harmonization** (Месяцы 3–5) | Развертывание Product/Reference MDM; настройка версионирования, процессов утверждения и публикации справочников. | Переход на использование канонических кодов; завершение формирования связей для устаревших систем. |
| **6. Lakehouse & Events** (Месяцы 4–7) | Развертывание Object Storage и зон Iceberg; внедрение Kafka и Trino; миграция исторических данных по операциям и каналам; интеграция DataHub Lineage. | Обеспечена возможность повторной обработки и подготовлены наборы данных для задач Antifraud и Data Science. |
| **7. Domain Waves** (Месяцы 6–11) | Поэтапный перенос доменов: CRM/Обращения → Продукты → Кредиты → Карты → Счета/Core. | Каждый домен переведен в целевой контур; финансовые домены переведены только после успешной сверки балансов. |
| **8. Decommission** (Месяцы 10–12) | Перевод легаси в режим только чтение; тестирование восстановления из архивов; остановка потоков; отзыв доступов и лицензий; обновление CMDB и инструкций. | Системы RB официально выведены из эксплуатации на основании актов; сервисы приняты в поддержку целевым контуром. |

**Ключевые правила проведения миграционных волн**
*   **Последовательность:** Начало следующей волны допускается только после завершения периода стабилизации предыдущей. Нефинансовые подготовительные работы могут выполняться параллельно.
*   **Ответственность:** Для каждой волны назначаются: владелц миграции; лицо, принимающее решение о переключении и дежурная команда.
*   **Риски:** Для каждой волны должен быть определен крайний срок отката.

## Контрольные точки

*   **Месяц 3:** Наличие Global Customer ID, утвержденной матрицы мастер-систем, работающих временных потоков, показателей DQ, витрин DWH, маппинга по BIAN и утвержденного плана на год.
*   **Месяц 6:** Функционирующий Reference Master, производственная среда Lakehouse, работающий каталог, успешно проведенное пробное переключение одного домена.
*   **Месяц 9:** Основные клиентские и продуктовые домены переведены на целевой контур; финансовые домены находятся в режиме параллельного запуска.
*   **Месяц 12:** Выполнение всех критериев выхода; устаревшие системы либо полностью отключены, либо имеют документированное исключение с указанием рисков и сроков поддержки.
