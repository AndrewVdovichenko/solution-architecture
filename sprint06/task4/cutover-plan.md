# План переключения: Клиентские данные

Данный документ определяет порядок перехода от текущей модели управления клиентскими данными к целевой архитектуре на базе Customer MDM.

## Ролевая модель управления

* **Cutover Manager:** Принимает операционные решения по управлению процессом, управляет изменениями в руководствах по миграции.
* **Customer Data Owner:** Обеспечивает бизнес-приемку и принимает ответственность за качество данных.
* **Technical Leads (MDM/CRM/Integration/DWH):** Ответственны за техническую реализацию и готовность своих компонентов.
* **Security & Service Desk:** Участвуют в принятии решения Go/No-Go и обеспечивают поддержку в период сразу после миграции.

## График и этапы переключения

| Фаза | Содержание работ | Критерии успешного завершения |
| :--- | :--- | :--- |
| **Подготовка** | Утверждение объёма проводимых работ; тестирование процедур бэкапа и восстановления; проведение учений на данных, идентичных продовому окружению; нагрузочное тестирование; уведомление пользователей; очистка очередей (DLQ). | Все дефекты высокого уровня важности устранены; план отката протестирован; мониторинговые панели в «зеленой» зоне. |
| **Готовность** | Фиксация версий схем и правил сопоставления; выгрузка базовых показателей; проверка готовности персонала и прав доступа. | Подписанный чек-лист готовности. |
| **Ограничение изменений** | Запрет на массовые операции слияния/разделения, изменение правил сопоставления и справочников. Обычные изменения в CRM принимаются и буферизируются через CDC. | Отсутствие полной остановки каналов; зафиксированный объем накопленных изменений. |
| **Загрузка** | Идемпотентная загрузка связей и золотых записей; помещение отклонений в карантин; применение накопленных изменений. | Отсутствие критических ошибок; задержка в рамках установленных лимитов. |
| **Сверка** | Сверка по количеству (регион/тип), контрольные суммы, проверка уникальности Global ID, полноты связей. | Порог: 100% уникальность ключевых ID, 0 необъяснимых критических расхождений; выборка одобрена Data Steward. |
| **Принятие решения** (Go/No-Go) | Проверка всех критериев владельцами доменов, службой безопасности и операционным управлением. | Письменное решение (Go/No-Go) с фиксацией времени. |
| **Переключение** | Перевод CRM/API на чтение Global ID и атрибутов из MDM; активация новых маршрутов; запуск синтетических проверок. | Новый маршрут активен; старый маршрут доступен только для отката. |
| **Усиленный мониторинг** (72ч после переключения) | Круглосуточный мониторинг API, CDC, DLQ, частоты слияний, устаревания профилей и жалоб клиентов. | Соблюдение SLA в течение 72 часов; отсутствие инцидентов высокого уровня важности. |
| **Стабилизация** (14 дней) | Устранение остаточных ошибок в карантине; повторный контроль качества (DQ) и подписание актов потребителями. | Перевод старого маршрута в режим «только чтение». |

## Критерии принятия решения (Go/No-Go Gates)

Для перехода к активной фазе переключения должны быть выполнены следующие условия:
1.  **Восстанавливаемость:** Успешно подтверждено восстановление из бэкапа на учениях по восстановлению; все системы (MDM, CRM, Broker, Monitoring) доступны.
2.  **Целостность потоков:** Задержка CDC (lag) ≤ 5 минут; в очередях DLQ отсутствуют критические события клиентов.
3.  **Чистота данных:** Отсутствуют конфликтующие подтвержденные идентификаторы в автоматически объединенных профилях; спорные записи успешно переведены в режим ручного разбора.
4.  **Валидация потребителей:** Все критически важные потребители прошли smoke-тестирование; бизнес-владельцы подписали результаты сверки.

## Управление откатом и точкой невозврата

**Процедура отката:**
До достижения «точки невозврата» маршрутизация возвращается к исходной схеме (CRM). Публикация в MDM приостанавливается, новые команды в MDM сохраняются в буфере, манифесты потребителей не удаляются. Изменения в CRM, произошедшие за период переключения, восстанавливаются через CDC. Новые Global ID при откате не переиспользуются.

**Точка невозврата:**
Наступает по истечении 14 дней стабильной работы системы, после получения формального подтверждения от потребителей и перевода старого маршрута в режим только чтение.

**После достижения точки невозврата:**
Откат к старой топологии невозможен. Физическое удаление устаревших систем производится отдельно и не является частью данного процесса.
