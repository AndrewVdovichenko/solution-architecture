# Технологическая дорожная карта

## Стратегия внедрения технологий

| Статус | Технологии / Подходы | Обоснование выбора |
| :--- | :--- | :--- |
| Внедрение | **Customer & Product MDM** | Необходимость обеспечения золотых записей, управления связями  и версионирования справочников уже на этапе MVP. |
| Внедрение | **PostgreSQL DWH + dbt/SQL** | Обеспечение оперативного получения согласованной отчетности и прозрачного управления трансформациями данных. |
| Внедрение | **CDC/Outbox, Integration Layer, Schema Contracts** | Переход от пакетной обработки к событийной модели; исключение точечных интеграций и предотвращение неконтролируемой двойной записи. |
| Внедрение | **Apache Airflow** | Оркестрация пакетных процессов, управление повторными попытками и контроль зависимостей. |
| Внедрение | **DataHub, DQ Framework, Observability** | Обеспечение управления метаданными, поиска, прослеживаемости, контроля качества и анализа влияния изменений. |
| Внедрение | **IAM/KMS, Tokenization, Masking, Audit** | Обеспечение базовой защиты персональных данных (ПДн), банковской тайны и платежных реквизитов. |
| Пилот | **Kafka + Schema Registry** (для CDC/Events) | Тестирование пропускной способности, стратегий партиционирования, механизмов повторных запросов и работы с очередями ошибок (DLQ). |
| Пилот | **Iceberg Lakehouse + Trino** | Тестирование обработки исторических данных (карточные операции), управления доступом и стоимости хранения. |
| Пилот | **Data Products (с контрактами и SLO)** | Апробация модели владения данными на примере Customer 360 и платежных доменов перед масштабированием модели. |
| Оценка | **Graph Projection** (для AML/Antifraud) | Оценка потенциала ускорения анализа связей; не является заменой MDM, требует подтвержденного бизнес-кейса. |
| Оценка | **Streaming Feature Pipelines / ML** | Использование в задачах антифрода после стабилизации потоков событий и внедрения управления моделями. |
| Запрет | **Аналитические запросы к OLTP** | Предотвращение рисков деградации производительности критически важных клиентских сервисов. |
| Запрет | **Расширение устаревших систем DWH/BI и локальных справочников** | Минимизация объема будущей миграции и исключение поддержки параллельных семантик данных. |
| Запрет | **Полноценный организационный Data Mesh** | Предотвращение фрагментации данных до создания единой платформы, закрепления владельцев и стандартизации контрактов. |

## График реализации (Implementation Sequence)

* **Месяцы 0–3:** Запуск MDM MVP, развертывание DWH, внедрение Airflow, базовых механизмов CDC, фреймворка качества (DQ) и каталога метаданных.
* **Месяцы 3–6:** Развертывание Product/Reference MDM, пилотное внедрение связки Kafka/Iceberg/Trino, обеспечение полного прослеживания для Customer 360 и отчетности.
* **Месяцы 6–9:** Масштабирование на полноразмерную историю событий, запуск полноценных Data Products, проведение первых доменных переключений.
* **Месяцы 9–12:** Масштабирование платформы на все домены, выполнение финальных финансовых миграций и вывод устаревших систем из эксплуатации.
