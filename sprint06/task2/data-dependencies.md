# Анализ рисков и зависимостей данных

| Риск / Зависимость | Последствия | Методы обнаружения | Меры по снижению рисков (Mitigation) |
| :--- | :--- | :--- | :--- |
| **Расхождения в идентификаторах клиентов** | Дублирование профилей, некорректные коммуникации и рост операционных рисков. | Анализ доли дублей, выборочный аудит. | Использование MDM, применение детерминированного и вероятностного сопоставления, процедуры ручного подтверждения и механизм разделения записей. |
| **Ошибочное слияние различных клиентов** | Нарушение конфиденциальности (раскрытие данных) и ненадлежащее обслуживание. | Жалобы клиентов, обнаружение конфликтующих уникальных ID, аудит Data Steward. | Установка консервативных порогов вероятности, использование отрицательных признаков, подтверждение вторым человеком. |
| **Несоответствие продуктовых и статусных кодов** | Формирование некорректных витрин данных и ошибок маршрутизации. | Проверка ссылочной целостности. | Назначение ответственных за справочники, карантин для неизвестных кодов. |
| **Двойная запись** | Расхождение данных между CRM, MDM и Core-системами. | Конфликты версий и ошибки при сверке данных. | Строгое закрепление единственного источника истины для каждого атрибута, использование паттерна Outbox/CDC, запрет на прямую запись в систему со стороны потребителей. |
| **Нарушение порядка событий (дублирование/потеря/перестановка)** | Искажение итоговых сумм или некорректный откат состояния систем. | Анализ пропусков, задержки, расхождение итогов источник-приемник. | Обеспечение идемпотентности, использование версионирования, механизмы повторов (retry/DLQ), возможность повторного воспроизведения из неизменяемого лога. |
| **Запаздывание финансовых событий** | Необходимость пересчета уже закрытой отчетности. | Мониторинг метрик данных. | Применение корректирующих загрузок, регламентированный процесс повторного открытия периодов. |
| **Неполная историческая выгрузка из RB** | Потеря исторического контекста и построение некорректных моделей риска. | Сверка количественных показателей, контрольных сумм по периодам. | Выгрузка сегментированными чанками, обязательная процедурная сверка. |
| **Избыточная нагрузка на OLTP через CDC** | Деградация производительности клиентских сервисов. | Мониторинг нагрузки на CPU/IO/Locks БД, лаг репликации. | Использование нативных логов или реплик для чтения, ограничение скорости, использование снапшотов и механизмов обратного давления. |
| **Недоступность MDM-системы** | Блокировка процессов создания и обогащения профилей. | Мониторинг SLO, глубины очередей, ошибок API. | Обеспечение высокой доступности (HA), использование кэша для чтения, очередей команд. |
| **Некорректное определение метрик** | Расхождение показателей в BI-системах и регуляторной отчетности. | Проверка сертификации метрик и параллельный расчет. | Ведение бизнес-словаря, процедура утверждения владельцами, версионирование изменений, отслеживание происхождения данных. |
| **Недостаточная защита ПДн в Data Lakehouse** | Риск массовой утечки персональных данных. | Аудит доступа, работа систем DLP, сканирование политик безопасности. | Токенизация, применение политик на уровне колонок и строк, разделение зон доступа, маскирование данных в непроизводственных средах. |

## Критические зависимости запуска MVP

* **Customer 360:** Прямая зависимость от полноты покрытия связей.
* **Объединенная отчетность:** Зависит от качества покрытия связей и корректности маппинга продуктовых справочников.
* **Регуляторная отчетность:** Публикация допускается только после завершения финансовой сверки и официального утверждения определений метрик.
* **Сертификация данных:** Отсутствие закрепленных владельцев данных и механизмов отслеживания происхождения блокирует придание наборам данных статуса «сертифицированных», даже при успешной технической приёмки данных.
