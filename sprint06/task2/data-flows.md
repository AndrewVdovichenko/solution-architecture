# Потоки данных промежуточного состояния

Диаграмма потоков данных **[DFD](diagrams/interim-data-flow.puml)** показывает целевое состояние архитектуры через три месяца.

**Важное примечание:** Операция `Delete` в потоках данных означает создание записи типа **tombstone** (маркер удаления/закрытия записи) и не подразумевает физического удаления финансовой истории из систем учета.

| ID потока | Маршрут (Источник → Приёмник) | Сущности и операции | Режим передачи | Назначение |
| :--- | :--- | :--- | :--- | :--- |
| **F1** | CRM FU/RB → Customer MDM | Клиент, ID, согласие; Create/Update/Delete/Validate/Deduplicate | Начальная загрузка (Batch) + асинхронный CDC | Формирование золотой записи и глобального ID. |
| **F2** | Customer MDM → CRM FU/RB и Integration Layer | Связи, эталонные атрибуты; Read/Enrich | Асинхронные события + Query API | Обогащение каналов взаимодействия единым профилем клиента. |
| **F3** | Core FU/RB → Integration Layer → DWH | Счета, договоры, платежи, транзакции; Create/Update | CDC (микро-батчи) | Формирование отчетности без нагрузки на операционную среду (OLTP). |
| **F4** | Карточный процессинг FU/RB → Integration Layer → DWH | Карты, карточные транзакции; Create/Update | Событийная модель / CDC | Сбор данных по карточным операциям и продуктам. |
| **F5** | Кредитный домен FU/RB → Integration Layer → DWH | Кредиты, графики, остатки; Create/Update | CDC + снапшоты | Формирование единого кредитного портфеля. |
| **F6** | Reference Hub → Операционные системы | Справочники продуктов, тарифов и кодов; Read/Enrich | Версионированные события / API | Синхронизация согласованных кодов при сохранении поддержки legacy-систем. |
| **F7** | Customer MDM → DWH | Измерения клиента и связи; Snapshot/CDC | Риалтайм + ежедневная сверка | Обеспечение связи транзакционных фактов обоих банков с единым клиентом. |
| **F8** | DWH → BI | Сертифицированные витрины данных; Read/Aggregate | Регламентированные задачи + управляемый SQL | Построение управленческой отчетности. |
| **F9** | DWH → Регулятор | Утвержденные выгрузки отчетности; Aggregate/Read | Согласно установленным регламентам | Формирование регуляторной отчетности. |
| **F10** | Pipelines/MDM/DWH → DataHub | Схемы, владельцы, происхождение, статус DQ | При развертывании + по расписанию | Обеспечение поиска, отслеживания происхождения данных и контроля качества (DQ). |

## Каноническая структура события

Все события в шине данных передаются в стандартизированной обертке:

```json
{
  "event_id": "uuid",
  "event_type": "customer.updated.v1",
  "entity_id": "global-id",
  "source_system": "RB_CRM",
  "source_record_id": "rb-id",
  "occurred_at": "RFC-3339 timestamp",
  "schema_version": 1,
  "correlation_id": "uuid",
  "payload": {}
}
