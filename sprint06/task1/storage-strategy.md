# Стратегия хранения

| Группа данных | Основное хранилище | Обоснование | Не является источником истины |
| :--- | :--- | :--- | :--- |
| Счета, договоры, платежи, проводки | Профильные ACID OLTP-системы | Обеспечение транзакционной целостности, управление блокировками и соблюдение строгих бизнес-инвариантов | DWH / Data Lakehouse |
| Клиентские данные и связи идентификаторов | Customer MDM | Процессы сопоставления, формирования golden record и слияния/разделения записей | CRM и аналитические витрины данных |
| Продукты, тарифы, общие коды | Product / Reference MDM | Управление версионированием, назначение владельцев данных и обеспечение единой публикации справочников | Локальные справочники отдельных приложений |
| Регуляторные и управленческие факты | DWH (Хранилище данных) | Наличие согласованной модели данных, возможность получения воспроизводимых срезов и контролируемых метрик | BI-системы и разовые выгрузки |
| Событийный поток и полная история изменений | Lakehouse | Масштабируемость при хранении больших объемов, schema evolution, обработка пакетов и потоков | Витрины данных без подтвержденного качества данных |
| Документы, архивы и исходные файлы | Объектное хранилище | Обеспечение неизменяемости, управление жизненным циклом и хранение тяжелых бинарных объектов | Поисковый индекс |
| Текстовые данные обращений | Поисковый индекс | Возможность полнотекстового поиска с применением фильтров разграничения доступа | CRM-система |
| Связи сторон и контрагентов | Графовая БД | Анализ многошаговых связей для противодействия отмыванию денег и систем антифрода | MDM / Core Banking |

## Разделение нагрузок OLTP и OLAP
Аналитические системы получают данные посредством механизмов CDC, потоковой передачи событий или через реплики для чтения и регулярные выгрузки. Запрещается выполнение ресурсоемких аналитических запросов к операционным системам.

- **DWH**: служит для хранения сертифицированных фактов и измерений, предназначенных для построения отчетности.
- **Lakehouse**: обеспечивает неизменяемое хранение исходных данных с последующей нормализацией в слое Silver и публикацией верифицированных наборов данных в слое Gold.
- **Регуляторная отчетность**: если набор данных используется для отчетности перед регулятором, его бизнес-логика фиксируется в DWH, а полученные результаты подлежат обязательной сверке с контрольными показателями из мастер-систем.

## Общие требования

- **Партиционирование**: транзакции должны быть партиционированы по бизнес-дате и источнику; техническое время загрузки данных хранится в отдельном атрибуте.
- **Управление историчностью**: для отслеживания изменений атрибутов клиента, продукта, тарифа и сегмента должен использоваться механизм SCD.
- **Целостность данных**: исходные данные должны храниться в неизменяемом виде, что обеспечивает возможность полного пересчета всех последующих слоев обработки данных.
- **Отказоустойчивость**: параметры репликации и резервирования определяются исходя из критичности систем; целевые показатели восстановления (RPO/RTO) должны быть подтверждены результатами анализа влияния на бизнес.
- **Управление жизненным циклом данных**: требования по локализации данных, срокам хранения, приостановке удаления и уничтожению данных должны быть интегрированы в общие политики платформы и не должны реализовываться вручную в рамках отдельных конвейеров данных.
