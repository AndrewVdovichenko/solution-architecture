# Логическая модель данных

[Исходник ERD](diagrams/logical-data-model.puml) отделяет сторону от банковских
продуктов и записей исполнения. Это позволяет связать один Customer 360 с
несколькими исходными профилями и сохранить юридически значимые записи в их
профильных системах.

## Основные правила

- Клиент имеет несколько идентификаторов, согласий, сегментов и обращений.
- Договор связывает клиента с версией продукта и применимым тарифом.
- Счёт является объектом учёта; карта и кредит связаны со счётом через договор.
- Транзакция отражает событие по счёту, платёж — бизнес-процесс перевода;
  один платёж может породить несколько транзакций.
- Продукт и тариф версионируются по периоду действия, чтобы исторические договоры
  не меняли смысл после обновления каталога.
- Остаток счёта не вычисляется из неполной аналитической истории и сверяется с Core.

Модель логическая: физические таблицы, партиционирование и денормализация выбираются
отдельно для OLTP, DWH и Lakehouse.
