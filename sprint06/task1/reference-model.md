# Использование BIAN

BIAN используется в качестве референсного словаря для определения границ ответственности. Это не подразумевает дословное копирование API или физической модели BIAN.

| Сущность | Сервисный домен BIAN (или близкая область) | Применение в FinUnion |
| :--- | :--- | :--- |
| **Клиент** | Party Reference Data Directory | Отделяет управление мастер-данными контрагента от каналов продаж и продуктов; база Customer MDM. |
| **Идентификатор, KYC** | Party Reference Data Directory / Customer Identification | Унифицирует идентификаторы и процедуры проверки (KYC) между FU и RB. |
| **Профиль и сегмент клиента** | Party Routing Profile | Описывает атрибуты для маршрутизации; концепция Customer 360 шире данного сервисного домена. |
| **Договор** | Customer Agreement | Фиксирует общие условия взаимодействия вне зависимости от продуктовых записей. |
| **Счёт** | Current Account | Закрепляет управление владением счётом и его жизненным циклом за Core Banking. |
| **Карта** | Credit Card / Issued Device Administration / Card Authorization | Разделяет понятия банковского продукта, устройства доступа и авторизации операции. |
| **Кредит** | Consumer Loan | Закрепляет график платежей, задолженность и статус за кредитным доменом. |
| **Платёж** | Payment Order / Payment Execution | Разделяет платёжную инструкцию, процесс исполнения и бухгалтерские транзакции. |
| **Продукт, тариф** | Product Directory | Создаёт единый каталог определений и версий продуктов. |
| **Обращение** | Contact Handler / Session Dialogue / Customer Case | Разделяет каналы контакта, ведение диалога и управление клиентскими кейсами. |


## Польза при слиянии

1. **Общий язык.** Локальные термины FU и RB сопоставляются с нейтральной
   банковской областью, а расхождения фиксируются в глоссарии.
2. **Границы владения.** Customer MDM владеет стороной, Core — счётом, Cards —
   картой, Loans — кредитом, Payments — процессом платежа.
3. **Поиск пересечений.** Две реализации одного домена становятся кандидатами на
   консолидацию, и при этом не смешиваются на уровне таблиц.
4. **Data products.** Customer 360, Accounts & Balances, Payments & Transactions и
   Credit Portfolio получают явные домены и владельцев.

Точное соответствие версии BIAN фиксируется при старте реализации. При смене названий областей в новых версиях каталога, приоритет отдается бизнес-значению сущности; при этом необходимо фиксировать версию каталога, на которой базируется описание
