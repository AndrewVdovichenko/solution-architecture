# DWH и Lakehouse

В рамках развития платформы данных реализуется гибридный подход, сочетающий строгую модель хранилища данных (DWH) для отчетности и гибкий Lakehouse для работы с большими объемами и сложной аналитикой.

## Этапы реализации

### Промежуточное состояние

На данном этапе **PostgreSQL DWH** принимает пакетные загрузки и CDC-копии из систем FU и RB. В DWH осуществляется нормализация связей для клиентов и продуктов, а также публикация минимально необходимого набора витрин (клиенты, счета, продукты, операции).

Для обеспечения возможности повторной обработки все исходные файлы сохраняются в неизменяемом виде в объектном хранилище (Object Storage). Прямые ресурсоемкие запросы к операционным системам (OLTP) строго запрещены.

### Целевое состояние
Разделение ролей между DWH и Lakehouse позволяет оптимизировать стоимость хранения и производительность вычислений.

| Категория данных | Роль в DWH | Роль в Data Lakehouse |
| :--- | :--- | :--- |
| **Регуляторные факты** | Сертифицированные версии данных и закрытые периоды. | Сырые копии данных и полная история трансформаций. |
| **Управленческие показатели** | Согласованные факты, измерения и витрины. | Промежуточные наборы данных для расчетов. |
| **Полная история транзакций** | Агрегаты и данные в пределах требуемого отчетного горизонта. | Полная детальная история всех событий. |
| **События (карты/digital)** | Итоговые агрегированные показатели. | Сырые и нормализованные потоки событий. |
| **Документы и архивы** | Метаданные и ссылки на объекты. | Сами объекты в Object Storage. |
| **Data Science / Anti-fraud** | Утвержденные результаты (если требуется для отчетности). | Основной слой вычислений и наборы признаков. |

Технологический стек базируется на Apache Iceberg, который обеспечивает табличный слой поверх файлов с поддержкой эволюции схем, эффективного партиционирования и атомарных операций. Для распределенного SQL-доступа к данным Lakehouse и другим источникам используется Trino.

## Архитектурные слои данных

- **Bronze (Слой сырых данных):** Хранение неизменяемого полезного содержимого, идентификатора источника, времени загрузки, исходной схемы и контрольных сумм. Доступ к слою максимально ограничен.
- **Silver (Слой нормализации):** Приведение данных к каноническим типам, дедупликация, нормализация кодов, применение глобальных идентификаторов (Global IDs) и изоляция отклонений в карантин.
- **Gold (Слой бизнес-данных):** Верифицированные доменные наборы данных и наборы признаков.
- **DWH Marts (Витрины отчетности):** Наборы данных, построенные по утвержденным бизнес-правилам, содержащие исторические измерения и данные по закрытым периодам с возможностью воспроизводимой сверки.

## Архитектурные ограничения и правила

- **Разграничение ответственности:** Data Lakehouse не является заменой ACID OLTP-системам и не может выступать мастером (SoR) для финансовых записей.
- **Ограничение использования Trino:** Trino предназначен для аналитических запросов; он не должен использоваться в качестве клиентского API.
- **Единство логики:** Запрещено реализовывать один и тот же показатель независимо в слоях Gold и DWH. Владелец данных обязан зафиксировать единую логику трансформации и проследить её происхождение.
