# Аналитическая модель транзакционных данных

Для обеспечения высокой производительности запросов и упрощения аналитических срезов выбрана архитектура **Звезда**. Данный подход позволяет минимизировать количество операций объединения данных через JOIN, обеспечивает четкое разделение измеримых событий и их описательных характеристик.

## Структура модели: Факты и Измерения

| Тип таблицы | Имя таблицы | Ключевые атрибуты |
| :--- | :--- | :--- |
| **Fact** | `fact_transaction` | Одна финальная или версионная транзакционная запись из источника; включает в себя сумму операции, остаток на счете после транзакции, комиссию, статус и временные метки. |
| **Fact** | `fact_account_balance_daily` | Состояние одного счета в разрезе валюты и бизнес-даты; включает в себя начальный баланс, сумму дебета, сумму кредита и конечный баланс. |
| **Dimension** | `dim_customer` | Версионная золотая запись клиента; не содержит чувствительных персональных данных. |
| **Dimension** | `dim_account` | Версия параметров счета. |
| **Dimension** | `dim_product` | Версия параметров продукта и актуального тарифа. |
| **Dimension** | `dim_date` / `dim_time` | Календарная сетка, банковские дни, периоды финансового закрытия. |
| **Dimension** | `dim_currency` | ISO-коды валют, параметры точности и служебные признаки. |
| **Dimension** | `dim_channel` | Каналы обслуживания: карты, отделения, мобильный банк, веб-интерфейс, переводы и др. |
| **Dimension** | `dim_branch` | Версия данных по отделениям и региональной принадлежности. |
| **Dimension** | `dim_transaction_status` | Канонические статусы транзакций и их маппинг в статусы источников. |

## Правила проектирования и целостности

- **Идентификация и точность:** В таблице `fact_transaction` в обязательном порядке сохраняются исходный бизнес-ключ и система-источник для обеспечения прослеживаемости и дедупликации. Денежные показатели хранятся с фиксированной точностью; использование типа `float` запрещено.
- **Управление валютами:** Суммы хранятся в валюте операции и валюте счета. Конвертация производится с использованием отдельной версии курса; исходная сумма операции не перезаписывается.
- **Временные измерения:** Связь факта с измерением времени осуществляется по бизнес-дате, а не по времени фактической загрузки данных в хранилище.
- **Управление изменениями статусов:** Любое изменение финального статуса транзакции инициирует создание управляемой версии или корректирующей записи; история изменений не удаляется.
- **Обработка неопределенных значений:** Для предотвращения потери фактов при отсутствии связи с измерением используется специальный технический ключ. Доля таких записей подлежит строгому мониторингу.
- **Контроль баланса:** Ежедневный баланс подлежит обязательной сверке по формуле:
  `Начальный баланс + Дебет − Кредит ± Корректировки = Конечный баланс` (с учетом знаковой модели системы учета).

## Аналитические возможности и безопасность

Модель позволяет осуществлять расчет оборотов и остатков в разрезе:
- Клиента (Customer 360);
- Продукта и тарифа;
- Канала обслуживания;
- Региона и отделения;
- Валюты и временного периода.

**Безопасность данных:**
Для защиты данных в DWH применяются политики разграничения доступа на уровне строк и колонок, а также изолированные защищенные связи с MDM. Системы BI не имеют прямого доступа к сканам документов и полным номерам карт (PAN).
