## Процесс MVP Unified Reporting

Алгоритм работы конвейера единой отчетности:

1.  **Экстракция:** Apache Airflow считывает CDC-staging. Полная первичная загрузка разбивается на сегменты по бизнес-дате или ключу.
2.  **Landing Layer:** Хранит исходные файлы, манифесты, счетчики записей, контрольные суммы по валютам в неизменяемом виде.
3.  **Staging Layer:** Выполняет проверку схем, типов данных и уникальности ключей. Записи, не прошедшие валидацию, перемещаются в карантин.
4.  **Обогащение:** С помощью MDM Crosswalk и Reference Hub локальные идентификаторы клиента и продукта заменяются на глобальные (Global IDs) без удаления исходных ключей.
5.  **Загрузка:** Инструментарий dbt обеспечивает идемпотентную загрузку измерений и таблиц фактов.
6.  **Сверка:** Процедура Source-to-Target проверяет количество записей, суммы, валюты, бизнес-даты и статусы. При обнаружении расхождений витрина данных (Mart) не получает статус сертифицированной.
7.  **Публикация:** После успешного прохождения тестов публикуются финальные представления и обновляются метаданные.

## Обработка больших данных

### 1. История карточных операций
- **Источники:** Карточные системы FU/RB и архивные выгрузки систем RB.
- **Характеристики:** Высокая плотность событий, наличие отложенных статусов, многолетняя глубина хранения.
- **Архитектура хранения:** Неизменяемое объектное хранилище и слои Bronze/Silver на базе Apache Iceberg. В DWH передаются только агрегаты и отчетно значимые факты.
- **Механизм обработки:** Сначала выполняется историческая пакетная загрузка, затем переход на CDC/Kafka. Реализована дедупликация по ID операции, упорядочивание по версии, токенизация PAN.
- **Потребители:** Antifraud, Risk, BI, Data Science.

### 2. События цифровых каналов
- **Источники:** Web-сайты, мобильные приложения, CRM/Контакт-центр.
- **Характеристики:** Потоковая природа, полуструктурированный формат, наличие анонимных или неполных идентификаторов.
- **Архитектура хранения:** Data Lakehouse. В DWH передаются только согласованные сессии и ключевые KPI.
- **Механизм обработки:** Потоковая обработка с использованием Schema Registry, фильтрация согласно политике согласий, построение сессий, обработка запоздалых событий и анонимизация данных согласно политике хранения.
- **Потребители:** Customer Journey, контроль качества сервиса, Antifraud, BI.
