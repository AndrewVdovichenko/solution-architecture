## Решение

Запуск системы будет осуществлен на базе **модульного монолита** с использованием управляемого PostgreSQL, асинхронных задач и заменяемых адаптеров для платежных систем, логистики и обмена сообщениями. Это единственный вариант, который соответствует ресурсам (6 инженеров), временным рамкам (8 недель) и бюджетному лимиту CFO в $5 000 в месяц на рекуррентные расходы на технологии, при этом сохраняя четко определенные границы для последующего выделения сервисов.

Сервис-ориентированный подход является целевым промежуточным состоянием после подтверждения соответствия продукта рынку. Целевые показатели CTO (40–50 сервисов, три кластера Kubernetes, Kafka, Istio, Oracle, multi-cloud и собственная система логистики) сохраняются как ориентир для масштабирования, но не являются базовыми требованиями для запуска.

## Ограничения модели

- Оценки взяты на глаз (погрешность ±30%), а не коммерческими предложениями вендоров.
- Для всех вариантов приняты единые допущения по спросу, среднему чеку (AOV), комиссиям платежных систем, инфляции и непредвиденным расходам.
- В структуре прямой TCO за пять лет преобладают транзакционные комиссии; поэтому TCO, управляемая архитектурой, выведена отдельно.
- Показатель инвестора в $12 000/минуту представлен как фактор чувствительности, а не как подтвержденный ожидаемый убыток.
